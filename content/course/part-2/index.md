> В этой части мы настраиваем не просто инструмент, а рабочую среду аналитика. Цель — сделать так, чтобы агент понимал структуру проекта, соблюдал договорённости, повторял полезные сценарии и при необходимости обращался к внешним источникам.

## Как читать команды в этой части

Все команды терминала рассчитаны на **Git Bash** в Windows и Bash/Zsh в macOS. Если команда начинается с `mkdir`, `cd`, `cat`, `find`, `grep`, `git` или `opencode`, её нужно вводить в терминале. Команды со слешем `/` в путях и переменными вида `$HOME` — это нормальный синтаксис Git Bash. Не вводите команды оболочки в поле запроса OpenCode.

Откройте Git Bash, перейдите в папку учебного проекта и проверьте расположение:

```bash
pwd
ls -la
git status --short
```

Если вы продолжаете работу с первой частью, используйте уже созданный учебный репозиторий. Если начинаете с чистого каталога:

```bash
mkdir -p ~/ai-analyst-course/docs
cd ~/ai-analyst-course
git init
mkdir -p .opencode/skills
```

В примерах `~/ai-analyst-course` означает папку проекта в домашнем каталоге. На Windows в Git Bash домашний каталог обычно соответствует профилю пользователя Windows.

Полезные команды для контроля изменений:

```bash
git status --short
git diff
git diff --stat
```

Перед работой с агентом полезно проверить, что вы находитесь в корне проекта: команда `pwd` покажет текущий каталог, а `ls -la` — его содержимое.
