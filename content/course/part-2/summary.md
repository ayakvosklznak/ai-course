В репозитории должны появиться:
- `docs/project-map.md` — навигация по проекту;
- `docs/source-register.md` — реестр источников;
- `AGENTS.md` — постоянные правила;
- `.opencode/skills/grill-me/SKILL.md` — уточнение требований;
- `.opencode/skills/requirements-review/SKILL.md` — ревью требований;
- `docs/mcp-notes.md` — описание MCP-сценария или учебного упражнения.

## Контрольный список

- [ ] Агент перечисляет источники, а не только пересказывает документы.
- [ ] Факты отделены от неизвестного.
- [ ] Противоречия фиксируются, а не разрешаются догадкой.
- [ ] `AGENTS.md` содержит короткие и проверяемые правила.
- [ ] Rules проверены на нескольких запросах.
- [ ] Skills имеют ясную область применения и протестированы.
- [ ] Сторонние skills проверяются до подключения.
- [ ] MCP используется только при реальной необходимости.
- [ ] Права MCP ограничены минимально необходимыми.
- [ ] Внешние данные не считаются доверенными инструкциями.

**Переход к части III.** Теперь у нас есть рабочая среда, контекст и повторяемые сценарии. Следующий шаг — создавать аналитические артефакты: от уточнения требований до спецификаций и архитектурных решений.
