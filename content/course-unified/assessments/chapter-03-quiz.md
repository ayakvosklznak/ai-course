## Вопросы

### 1. Зачем нужен `.gitignore`?

- A. Чтобы ускорить Git.
- B. Чтобы исключить зависимости, кэши и секреты из истории.
- C. Чтобы удалить файлы из проекта.
- D. Чтобы создать ветку.

### 2. Чем `git diff` отличается от `git diff --staged`?

- A. Ничем.
- B. Первый показывает изменения рабочего каталога, второй — изменения в индексе.
- C. Первый показывает коммиты, второй — ветки.
- D. Первый работает только с новыми файлами.

### 3. Новый файл не отображается в `git diff`. Почему?

- A. Git сломан.
- B. Файл не отслеживается, пока не добавлен в индекс.
- C. Файл слишком большой.
- D. Нужно выполнить `git push`.

### 4. Какая команда откатывает изменение в рабочем каталоге?

- A. `git restore <файл>`.
- B. `git push`.
- C. `git log`.
- D. `git branch`.

### 5. Какая команда потенциально уничтожает незакоммиченные изменения?

- A. `git status`.
- B. `git diff`.
- C. `git reset --hard`.
- D. `git log`.

### 6. Секрет попал в коммит. Что делать?

- A. Удалить строку следующим коммитом и считать вопрос закрытым.
- B. Считать секрет скомпрометированным, отозвать или ротировать его и удалить из истории.
- C. Добавить файл в `.gitignore`.
- D. Ничего: история приватная.

### 7. Агент изменил 10 файлов, из них 8 — лишние. Что делать?

## Ответы и разбор

<details>
<summary>Показать ответы</summary>

1. **B** — `.gitignore` защищает историю от зависимостей, кэшей, локальных конфигов и секретов.
2. **B** — `git diff` сравнивает рабочий каталог с индексом, `git diff --staged` — индекс с последним коммитом.
3. **B** — неотслеживаемый файл не попадает в diff, пока его не добавить через `git add`.
4. **A** — `git restore <файл>` возвращает файл к состоянию из индекса или коммита.
5. **C** — `git reset --hard` удаляет незакоммиченные изменения; используйте с осторожностью.
6. **B** — после попадания в историю секрет считается скомпрометированным: нужна ротация и очистка истории.
7. Проверить `git status` и `git diff`, откатить лишние файлы через `git restore`, оставить полезные изменения и закоммитить только их.

</details>
