**Время:** 60–75 минут.  
**Трек:** базовая для всех.

## Цели главы

После главы вы сможете:

- объяснить, чем skill отличается от rules, промпта и MCP;
- описать структуру skill: назначение, условия, шаги, ограничения, результат;
- подключить готовый skill и проверить его безопасность;
- создать собственный skill для регулярной задачи;
- оценить качество и поддерживать версии.

## Ключевые понятия

- **Skill** — переиспользуемый сценарий работы агента с шагами, ограничениями и ожидаемым результатом.
- **Триггер** — условие, при котором skill применяется.
- **Вход** — данные, необходимые для запуска сценария.
- **Ограничение** — что skill не должен делать.
- **Артефакт** — результат выполнения skill.

## Содержание

### 6.1. Зачем выносить сценарий в skill

- Повторяемость и единый формат результата.
- Снижение зависимости от формулировки промпта.
- Возможность проверить и улучшить процесс.
- Когда skill не нужен: разовая задача, простой запрос.

### 6.2. Skill, rules и prompt

- Rules задают постоянные ограничения.
- Prompt задаёт конкретную задачу.
- Skill задаёт последовательность действий и проверок.
- MCP даёт доступ к внешним инструментам, но не описывает процесс.

### 6.3. Структура skill

- Название и назначение.
- Когда применять и когда не применять.
- Необходимые входы.
- Пошаговый алгоритм.
- Ограничения и запреты.
- Формат результата.
- Критерии проверки.

### 6.4. Базовые сценарии для любой роли

- **Project Discovery** — исследование незнакомого репозитория.
- **Grill Me** — интервью для выявления скрытых требований.
- **Requirements Review** — проверка полноты и непротиворечивости.
- **Edge Cases** — поиск граничных и ошибочных сценариев.
- **ADR Draft** — подготовка проекта архитектурного решения.
- **Change Review** — проверка изменений по спецификации.

Ролевые варианты: `code-review` и `test-plan`, `incident-review`, `release-checklist`, `risk-review`.

### 6.5. Как подключить готовый skill

- Где искать и как читать инструкции skill.
- Проверка на опасные действия: удаление, публикация, сетевые вызовы, работа с секретами.
- Проверка источника и версии.
- Ограничение области применения.

### 6.6. Как создать свой skill

- Выбрать повторяющуюся задачу с проверяемым результатом.
- Зафиксировать входы и ожидаемый артефакт.
- Описать шаги и точки проверки.
- Добавить запреты и условия остановки.
- Проверить на двух разных задачах.
- Упростить и убрать лишнее.

### 6.7. Качество и поддержка

- Признаки хорошего skill: воспроизводимость, понятные входы, проверяемый результат.
- Признаки плохого: противоречивые шаги, скрытые допущения, отсутствие ограничений.
- Версионирование и журнал изменений.
- Когда удалить skill.

### 6.8. Практика

1. Выберите регулярную задачу из своего трека.
2. Создайте skill с шагами, ограничениями и форматом результата.
3. Прогоните его на двух разных входных задачах.
4. Сравните результаты и доработайте формулировки.
5. Проверьте, что skill не выполняет небезопасных действий без подтверждения.

## Проверка результата

- [ ] Skill имеет назначение, входы, шаги и критерии проверки.
- [ ] Указано, когда skill не применять.
- [ ] Есть ограничения и условия остановки.
- [ ] Результат воспроизводим на двух задачах.
- [ ] Сторонние инструкции проверены на безопасность.

## Адаптации по ролям

| Роль | Пример skill | Проверка результата |
|---|---|---|
| Разработчик | `code-review` | Замечания привязаны к строкам и правилам |
| QA | `test-plan` | Сценарии покрывают ошибки и границы |
| DevOps / SRE | `incident-review` | Есть таймлайн, причина, действия и профилактика |
| Аналитик | `requirements-review` | Требования проверяемы и прослеживаемы |
| Менеджер / продукт | `risk-review` | Риски оценены, владельцы и сроки указаны |
