**Время:** 45–60 минут.  
**Трек:** обязательна для DevOps, разработчиков и аналитиков; для остальных — по необходимости.

## Цели главы

После главы вы сможете:

- объяснить, что такое MCP и из каких частей он состоит;
- определить, когда нужен MCP, а когда достаточно файлов, API или skill;
- подключить MCP-сервер и настроить минимальные привилегии;
- оценить риски prompt injection и недоверенных данных;
- проверить пользу интеграции и при необходимости отключить её.

## Ключевые понятия

- **MCP** — протокол подключения внешних источников и инструментов к агенту.
- **MCP-сервер** — приложение, предоставляющее инструменты и ресурсы.
- **MCP-клиент** — агент, который вызывает сервер.
- **Инструмент** — действие, доступное через MCP.
- **Ресурс** — данные, которые сервер отдаёт агенту.
- **Минимальные привилегии** — доступ только к тому, что нужно для задачи.

## Содержание

### 7.1. Зачем нужен MCP

- Данные вне репозитория: трекер, база знаний, документация, логи, мониторинг.
- Действия: создать задачу, получить статус пайплайна, прочитать метрику.
- Границы: MCP не заменяет понимание задачи и проверку источников.

### 7.2. Основные понятия

- Клиент, сервер, инструменты, ресурсы, аутентификация.
- Локальные и удалённые серверы.
- Транспорт и способ запуска.
- Права и согласия пользователя.

### 7.3. MCP, API и skills

- API — программный интерфейс, который вы вызываете сами.
- MCP — способ дать агенту доступ к инструментам и данным.
- Skill — сценарий работы, который может использовать MCP.
- Когда достаточно скопировать документ в репозиторий.

### 7.4. Когда MCP нужен

- Данные часто меняются и нужны в актуальном виде.
- Объём данных слишком велик для ручного копирования.
- Нужны повторяемые запросы к трекеру, CI или мониторингу.
- Есть контролируемый доступ и понятные риски.

### 7.5. Подключение

- Выбор сервера и проверка источника.
- Настройка конфигурации и авторизации.
- Ограничение набора инструментов.
- Проверка подключения на простом запросе.
- Как отключить сервер и отозвать доступ.

### 7.6. Учебный сценарий

- Получить задачу из трекера через MCP.
- Сопоставить её с требованиями и кодом в репозитории.
- Найти расхождения и открытые вопросы.
- Не выполнять изменений во внешней системе без подтверждения.

### 7.7. Безопасность

- Prompt injection из внешних документов и комментариев.
- Почему данные из MCP считаются недоверенными.
- Запрет на передачу секретов и персональных данных.
- Ограничение необратимых действий.
- Журналирование и проверка действий.

### 7.8. Практика

1. Выберите один сценарий: задача из трекера, документация провайдера или статус пайплайна.
2. Подключите сервер с минимальными правами.
3. Получите данные и сопоставьте их с репозиторием.
4. Зафиксируйте, какие данные передавались и какие действия были разрешены.
5. Опишите ограничения и способ отключения.

## Проверка результата

- [ ] Могу объяснить, зачем подключён MCP, а не использован другой способ.
- [ ] Настроены минимальные права и подтверждения.
- [ ] Данные из внешнего источника проверены по репозиторию.
- [ ] Описаны риски и способ отключения.
- [ ] Нет передачи секретов и лишних персональных данных.

## Адаптации по ролям

| Роль | Источник | Риск |
|---|---|---|
| Разработчик | Трекер, CI, документация API | Изменение задачи или кода без подтверждения |
| QA | Трекер, тестовые прогоны, отчёты | Ложные данные о покрытии и статусах |
| DevOps / SRE | Мониторинг, CI/CD, облако | Необратимые инфраструктурные действия |
| Аналитик | База знаний, схемы, документация | Устаревшие или противоречивые сведения |
| Менеджер / продукт | Трекер, дашборды | Ложная уверенность в статусе и метриках |
