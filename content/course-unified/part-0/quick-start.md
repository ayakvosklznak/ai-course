**Время:** 90 минут.  
**Результат:** учебный репозиторий, `AGENTS.md`, карта проекта, первый проверенный diff и коммит.

Этот сценарий можно пройти бесплатно. Он показывает формат курса: короткая теория, действие, проверка и артефакт.

## Что понадобится

- Git, Node.js и CLI-агент (OpenCode).
- Доступ к модели.
- 90 минут без прерываний.
- Пустая папка для учебного проекта.

Если чего-то не хватает, сначала выполните [setup guide](setup-guide.md). Не устанавливайте инструменты «по памяти»: сверяйте команды с официальной документацией.

## Шаг 1. Проверьте окружение (10 минут)

Откройте Git Bash в Windows или Terminal в macOS:

```bash
git --version
node --version
npm --version
opencode --version
```

Все четыре команды должны вывести версии. Если `opencode` не найден, вернитесь к [setup guide](setup-guide.md).

Проверьте, что вы не находитесь в чужом проекте:

```bash
pwd
```

## Шаг 2. Создайте учебный репозиторий (5 минут)

```bash
mkdir -p ~/ai-agent-course/docs
cd ~/ai-agent-course
git init
git config user.name "Course Student"
git config user.email "student@example.local"
printf '%s\n' '.env' 'node_modules/' '.DS_Store' > .gitignore
printf '# Учебный проект\n\nСистема обработки заказов.\n' > README.md
git add .
git commit -m "chore: init training repo"
```

Эти команды создают только локальный репозиторий и не затрагивают другие проекты.

## Шаг 3. Получите обзор проекта от агента (10 минут)

Запустите агента из корня репозитория:

```bash
opencode
```

Отправьте запрос:

```text
Ты работаешь в учебном репозитории.
1. Перечисли структуру проекта и назначение каждого файла.
2. Отметь, чего не хватает для задачи «уведомления о статусе заказа».
3. Не изменяй файлы.
4. Для каждого утверждения укажи файл-источник.
```

Проверьте ответ: агент должен ссылаться на реальные файлы, а не придумывать содержимое. Если он выдумал файл, отметьте это и повторите запрос с требованием проверять структуру.

## Шаг 4. Создайте `AGENTS.md` (15 минут)

Скопируйте шаблон [AGENTS.template.md](../templates/AGENTS.template.md) в корень проекта под именем `AGENTS.md` и заполните:

- назначение проекта;
- стек и структуру;
- команды проверки;
- соглашения;
- источники истины;
- границы и запреты.

Минимальный вариант:

```markdown
# AGENTS.md

## О проекте
Учебный репозиторий для курса. Система обработки заказов.

## Границы
- Не изменяй файлы вне `docs/` без подтверждения.
- Не выполняй `git push`, `git reset --hard` и удаление файлов.
- Не добавляй секреты и персональные данные.
- Перед изменением покажи план.

## Проверка результата
- Изменения проверяются через `git diff`.
- Каждое утверждение о проекте должно ссылаться на файл.
```

Сохраните файл и проверьте, что агент его видит:

```text
Перечисли правила из AGENTS.md, которые ограничивают твои действия. Не изменяй файлы.
```

## Шаг 5. Выполните первую задачу (30 минут)

Создайте файл `docs/first-task.md`:

```bash
printf '# Первая задача\n\nНужно уведомлять пользователя об изменении статуса заказа.\n' > docs/first-task.md
git add docs/first-task.md
git commit -m "docs: add first task"
```

Отправьте агенту запрос:

```text
Задача: дополни docs/first-task.md.
Добавь раздел «Открытые вопросы» с пятью вопросами, которые нужно задать владельцу продукта.
Добавь раздел «Допущения» с тремя учебными допущениями, явно помеченными как неподтверждённые.
Не изменяй другие файлы.
Сначала покажи план, затем изменения.
```

Порядок работы:

1. Прочитайте план агента.
2. Убедитесь, что он не собирается менять другие файлы.
3. Разрешите изменение.
4. Проверьте результат:

```bash
git status --short
git diff
```

5. Если есть лишние изменения, откатите их:

```bash
git restore <файл>
```

6. Закоммитьте полезный результат:

```bash
git add docs/first-task.md
git commit -m "docs: add open questions for notification task"
```

## Шаг 6. Проверьте результат (10 минут)

- [ ] Агент запускался из корня проекта.
- [ ] В ответе об обзоре были ссылки на реальные файлы.
- [ ] `AGENTS.md` создан и ограничивает действия агента.
- [ ] Первая задача выполнена без лишних изменений.
- [ ] Diff прочитан до коммита.
- [ ] В истории нет секретов.
- [ ] Я могу объяснить, что и зачем изменено.

## Мини-квиз

1. Чем агент отличается от чата?
2. Почему ответ агента без ссылок на файлы считается рискованным?
3. Зачем нужен `AGENTS.md`?
4. Почему diff нужно читать до коммита?
5. Что делать, если агент изменил лишний файл?

<details>
<summary>Ответы</summary>

1. Агент может читать и изменять файлы и выполнять команды, а не только генерировать текст.
2. Без источника утверждение нельзя проверить; оно может быть выдумано.
3. Он задаёт постоянные правила и границы, чтобы не объяснять их в каждой задаче.
4. Diff показывает фактические изменения и позволяет откатить лишнее до фиксации в истории.
5. Откатить файл через `git restore` и уточнить правило в `AGENTS.md`.

</details>
