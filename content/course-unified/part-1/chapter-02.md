**Время:** 90–120 минут.  
**Трек:** обязательна для всех; DevOps и разработчики выполняют расширенную проверку окружения.

## Цели главы

После главы вы сможете:

- подготовить окружение и установить CLI-агента;
- подключить облачную или локальную модель и проверить доступ;
- настроить разрешения на чтение, запись и выполнение команд;
- запустить агента в Git-репозитории и получить обзор проекта;
- диагностировать типовые ошибки установки и авторизации.

## Ключевые понятия

- **CLI-агент** — агент, работающий в терминале и имеющий доступ к файлам проекта.
- **Провайдер** — поставщик доступа к модели: облачный API, подписка или локальный сервер.
- **API-ключ** — секрет для доступа к провайдеру; не хранится в репозитории.
- **Разрешения** — правила, какие действия агент выполняет сам, а какие требует подтверждения.
- **Локальная модель** — модель, запущенная на своём оборудовании; данные не уходят наружу.

## Содержание

### 2.1. Подготовка окружения

- Windows: Git for Windows и Git Bash; macOS: Terminal и Git из Command Line Tools.
- Проверка `git`, `node`, `npm`; установка Node.js при необходимости.
- Рабочая папка курса и учебный Git-репозиторий.
- Разделение глобальных и проектных настроек.

### 2.2. Установка OpenCode

- Способы установки и проверка команды `opencode`.
- Типовые ошибки: команда не найдена, неверный PATH, устаревшая версия.
- Обновление и проверка версии.
- Примечание о переносимости: те же шаги для Copilot CLI, Claude Code и других агентов отличаются командами, но не концепциями.

### 2.3. Подключение модели

- Выбор провайдера: подписка, API-ключ, локальный совместимый сервер.
- Где получить ключ и куда его вставить; переменные окружения.
- Выбор модели под задачу: качество рассуждений, скорость, стоимость, размер контекста.
- Локальная модель: требования к оборудованию, ограничения качества.
- Проверка авторизации и сохранения настроек.

### 2.4. Разрешения и безопасность

- Режимы подтверждения действий.
- Что разрешать автоматически в учебном репозитории и что подтверждать всегда.
- Запрет на доступ к домашним каталогам, секретам и чужим проектам.
- Отключение агента и удаление ключей при завершении работы.

### 2.5. Первый запуск в репозитории

- Запуск из корня проекта.
- Запрос на обзор структуры и проверка, какие файлы агент прочитал.
- Сравнение ответа без контекста и с контекстом.
- Как выйти из агента и вернуться в терминал.

### 2.6. Диагностика

- Не находится команда: PATH и переустановка.
- Ошибка авторизации: ключ, провайдер, сеть.
- Модель не отвечает: лимиты, регион, выбранная модель.
- Агент не видит файлы: неверный рабочий каталог, права доступа, `.gitignore`.

### 2.7. Практика

1. Установите OpenCode и подключите доступную модель.
2. Создайте учебный репозиторий и запустите агента из его корня.
3. Попросите агента перечислить структуру проекта и источники, на которые он опирался.
4. Проверьте, что агент не может прочитать файл вне проекта, и зафиксируйте настройки разрешений.
5. Сохраните конфигурацию (без ключей) в заметке.

## Проверка результата

- [ ] Агент запускается из корня учебного репозитория.
- [ ] Модель отвечает, авторизация сохраняется между запусками.
- [ ] Ключи не находятся в файлах репозитория.
- [ ] Настроены подтверждения для изменения файлов и выполнения команд.
- [ ] Могу объяснить, какую модель выбрал и почему.

## Адаптации по ролям

| Роль | Что усилить | Пример задачи |
|---|---|---|
| Разработчик | Локальный запуск, тесты, линтеры | Проверить, что агент видит команды сборки и тестов |
| QA | Тестовые окружения и данные | Проверить доступ к тестовому конфигу без секретов |
| DevOps / SRE | Локальные модели, доступ к инфраструктуре | Настроить минимальные разрешения и отдельный профиль |
| Аналитик | Работа с документацией | Проверить чтение Markdown, JSON и схем |
| Менеджер / продукт | Безопасный обзор без изменения файлов | Запустить агента в режиме только чтения |
