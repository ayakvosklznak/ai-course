**Время:** 2–3 часа.  
**Для кого:** backend, frontend, fullstack, мобильные разработчики.

## Профиль роли

Разработчик чаще всего использует агента для чтения незнакомого кода, планирования изменения, написания тестов, рефакторинга и разбора ошибок. Главные риски: лишние изменения, слабые тесты, выдуманные API и секреты в коде.

## Чему учит трек

- планировать изменение до генерации кода;
- удерживать минимальный diff;
- проверять реализацию тестами, а не текстом ответа;
- проверять обратную совместимость и миграции;
- оформлять PR так, чтобы ревьюер видел доказательства.

## Практика

### Задание 1. Изменение с планом и тестами

1. Дайте агенту задачу: добавить обработку повторного события в учебном сервисе уведомлений.
2. Потребуйте сначала план: файлы, риски, тесты, что не входит.
3. Проверьте план и только затем разрешите изменение.
4. Запустите тесты и добавьте недостающие сценарии.
5. Проверьте diff на лишние изменения.

### Задание 2. Рефакторинг без изменения поведения

1. Выберите небольшой участок кода.
2. Попросите рефакторинг с условием: поведение не меняется, тесты остаются зелёными.
3. Сравните diff до и после.
4. Найдите изменения форматирования или лишние зависимости.
5. Откатите всё, что не относится к задаче.

### Задание 3. Изменение контракта

1. Добавьте поле в ответ API уведомлений.
2. Проверьте обратную совместимость и версионирование.
3. Обновите спецификацию и тесты.
4. Подготовьте описание PR: что, зачем, как проверено, что не входит.

## Артефакты трека

- `docs/dev/change-plan.md` — план изменения.
- `docs/dev/test-notes.md` — какие тесты добавлены и почему.
- `docs/dev/pr-description.md` — описание изменений.
- Обновлённая спецификация контракта.

## Рекомендации для `AGENTS.md`

- Команды сборки, тестов и линтера.
- Запрет на добавление зависимостей без подтверждения.
- Запрет на изменение несвязанных файлов и массовое переформатирование.
- Требование прикладывать результаты тестов.
- Правила работы с секретами и конфигурациями.

## Skills и MCP

- Skills: `change-plan`, `code-review`, `bug-triage`, `test-plan`.
- MCP: статус CI, задача из трекера, документация API.
- Ограничение: MCP не должен иметь права мержить или деплоить.

## Чек-лист качества

- [ ] Изменение соответствует спецификации.
- [ ] Diff минимален и объясним.
- [ ] Тесты покрывают новый и ошибочный сценарий.
- [ ] Нет секретов и лишних зависимостей.
- [ ] Описание PR содержит доказательства проверки.

## Типичные ошибки

- Принять код без запуска тестов.
- Разрешить агенту «улучшить» несвязанные файлы.
- Поверить в несуществующий метод или параметр.
- Оставить тест, который проверяет реализацию, а не поведение.
- Закоммитить конфиг с ключом.
