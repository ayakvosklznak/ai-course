**Время:** 2–3 часа.  
**Для кого:** инженеры по тестированию, QA-лиды, автоматизаторы.

## Профиль роли

QA использует агента для разбора требований, тест-дизайна, поиска граничных сценариев, подготовки тестовых данных и оформления дефектов. Главные риски: выдуманные шаги, неполное покрытие, ложные доказательства и персональные данные в тестовых наборах.

## Чему учит трек

- выводить тест-план из требований и спецификации;
- системно искать граничные и ошибочные сценарии;
- оформлять дефект так, чтобы его можно было воспроизвести;
- прикладывать доказательства, а не утверждения;
- проверять регрессию и не расширять объём без необходимости.

## Практика

### Задание 1. Тест-план по спецификации

1. Возьмите спецификацию уведомлений о статусе заказа.
2. Составьте тест-план: области, риски, окружения, данные.
3. Свяжите каждый пункт с требованием.
4. Найдите требования без проверки.
5. Проведите ревью плана с разработчиком.

### Задание 2. Граничные сценарии

1. Попросите агента найти граничные и ошибочные сценарии.
2. Проверьте предложения: повторы, тайм-ауты, частичные отказы, 429, недоступность провайдера.
3. Отделите подтверждённые сценарии от предположений.
4. Добавьте ожидаемый результат и критерий прохождения.
5. Уберите сценарии, которые невозможно проверить.

### Задание 3. Дефект-репорт

1. Возьмите заранее подготовленный дефект в учебном репозитории.
2. Оформите отчёт: шаги, ожидаемое и фактическое поведение, окружение, доказательства.
3. Проверьте воспроизводимость по своим шагам.
4. Укажите влияние и приоритет.
5. Свяжите дефект с требованием и тест-кейсом.

## Рекомендации для `AGENTS.md`

- Запрет на изменение продуктового кода и данных.
- Правила тестовых данных: синтетика, маскирование, отсутствие персональных данных.
- Требование указывать окружение и версию.
- Требование прикладывать доказательства.
- Запрет на «подтверждение» результата без прогона.

## Skills и MCP

- Skills: `test-plan`, `edge-cases`, `defect-report`, `regression-scope`.
- MCP: чтение задачи из трекера, результаты CI, тестовые прогоны.
- Ограничение: только чтение статусов; без запуска изменений в продуктовой среде.

## Чек-лист качества

- [ ] Каждый тест-кейс связан с требованием.
- [ ] Покрыты основные, альтернативные и ошибочные сценарии.
- [ ] Шаги воспроизводимы.
- [ ] Доказательства приложены.
- [ ] Тестовые данные безопасны.

## Типичные ошибки

- Придуманные шаги и ожидаемые результаты.
- Покрытие только happy path.
- Отчёт без окружения и доказательств.
- Персональные данные в тестовом наборе.
- Автоматизация проверок, которые ничего не проверяют.
