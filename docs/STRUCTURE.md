Карта репозитория: что где лежит, что является источником истины и что можно менять.

## Схема

```text
ai-course/
├── README.md                          навигация по репозиторию и карта файлов
├── docs/                              рабочие документы, не учебный текст
│   ├── STRUCTURE.md                    этот файл
│   ├── plan/
│   │   ├── plan_of_the_course.md       замысел базового курса (для аналитиков)
│   │   └── plan_unified.md             замысел обобщённого курса
│   ├── archive/
│   │   └── course-v1.0.1/              снимок базового курса: 4 файла-«книги»
│   │       └── README.md               правила работы с архивом
│   ├── product/
│   │   ├── offer.md                    позиционирование, издания, цены, метрики
│   │   └── landing.md                  черновик продающей страницы
│   └── useful_links.md                 внешние ссылки
└── content/                           учебный контент
    ├── course/                         базовый курс: 14 глав + части + итоги
    └── course-unified/                 обобщённый курс: часть 0, части I–V,
                                        templates/, assessments/, source-map.md
```

## Два источника истины

| Продукт | Каталог | Аудитория | Статус |
|---|---|---|---|
| Базовый курс | [content/course](../content/course/index.md) | Системные, бизнес-, продуктовые, дата-аналитики | `published`, v1.0.1 |
| Обобщённый курс | [content/course-unified](../content/course-unified/index.md) | Разработчики, QA, DevOps/SRE, аналитики, менеджеры | `draft`, v0.2 |

Больше источников истины нет. Всё остальное — либо документы о них, либо архив.

## Роли каталогов

| Каталог | Роль | Можно ли править контент |
|---|---|---|
| `content/` | Учебный текст, который отдаётся читателю | Да, это основная работа |
| `docs/plan/` | Замысел и редакционные правила | Да, при изменении концепции |
| `docs/archive/` | Замороженный снимок | Нет, только читать |
| `docs/product/` | Упаковка и продажи | Да |
| `README.md` | Навигация | Да |

## Почему план лежит в `docs`, а не в `content`

- `content/` — слой публикации: у файлов есть `title`, `part`, `chapter`, `order`, `kind`, `status` для рендерера и навигации.
- План — авторский документ: концепция, распределение времени, редакционный подход. Он не является главой курса и не должен попадать в выдачу.
- План появился раньше контента (первый коммит), а `content/` создавался позже под уже написанный текст.

## Почему `docs/archive/course-v1.0.1` — не дубль

Это тот же текст, что в `content/course`, но в исходной «книжной» разбивке. Различия только структурные: заголовок главы перенесён в front-matter, уровень заголовков понижен, разделители между главами убраны. Архив нужен для истории и сравнения формулировок, а не для правок.

Подробнее — в [docs/archive/course-v1.0.1/README.md](archive/course-v1.0.1/README.md).

## Как связаны базовый и обобщённый курсы

| Связь | Где зафиксирована |
|---|---|
| Что взято из базовых глав, что заменено, что добавлено | [content/course-unified/source-map.md](../content/course-unified/source-map.md) |
| Позиционирование и издания | [docs/product/offer.md](product/offer.md) |
| Замысел и этапы | [docs/plan/plan_unified.md](plan/plan_unified.md) |
| Замысел базового курса | [docs/plan/plan_of_the_course.md](plan/plan_of_the_course.md) |

Обобщённый курс не копирует базовый: он переиспользует метод и часть текста, добавляет часть 0, ролевые треки, шаблоны, квизы и рубрику capstone.

## Правила, чтобы не плодить копии

1. Правка учебного текста — только в `content/`.
2. Не создавать третий файл с тем же содержанием «на всякий случай».
3. Если нужен снимок версии — делать его в `docs/archive/` и помечать дату и версию.
4. При переносе файлов обновлять ссылки и проверять их.
5. Планы и редакционные правила не дублировать в `content/`.

## Проверка ссылок

После переименований проверяйте относительные ссылки во всех `.md`: они не должны указывать на удалённые пути. Быстрая проверка из PowerShell:

```powershell
$root = "A:\src\ai-course"
Get-ChildItem $root -Recurse -File -Filter *.md | Where-Object { $_.FullName -notmatch '\\\.git\\' } | ForEach-Object {
  $file = $_
  foreach ($m in [regex]::Matches([System.IO.File]::ReadAllText($file.FullName), '\]\(([^)]+)\)')) {
    $t = $m.Groups[1].Value
    if ($t -match '^(https?:|mailto:|#)') { continue }
    $p = $t.Split('#')[0]
    if ([string]::IsNullOrWhiteSpace($p)) { continue }
    $full = [System.IO.Path]::GetFullPath((Join-Path $file.DirectoryName $p))
    if (-not (Test-Path -LiteralPath $full)) { "$($file.FullName): $t" }
  }
}
```
