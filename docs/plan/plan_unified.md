## 1. Задача

Сделать один курс, который проходят специалисты разных специальностей, имеющие доступ к AI-агенту: разработчики, QA, DevOps/SRE, аналитики, менеджеры. Без пяти отдельных курсов и без «курса для всех» без содержания.

**Решение:** общее ядро + ролевой трек.

| Слой | Что даёт | Кто проходит |
|---|---|---|
| Часть 0 | Первый проверяемый результат за 90 минут | Все |
| Ядро I–IV | Метод: контекст, правила, сценарии, артефакты, процесс, безопасность | Все |
| Часть V | Артефакты, риски и практика конкретной роли | Один трек по выбору |
| Сквозная практика | Итоговый пакет артефактов и ревью | Все |

## 2. Принципы

1. **Метод один — артефакты разные.** Ядро не упоминает роль там, где это не нужно.
2. **Инструмент — средство.** OpenCode как reference implementation; концепции переносимы.
3. **Проверяемость.** У каждого модуля есть критерий результата, у каждой главы — квиз.
4. **Ранний результат.** Пользу видно до окончания курса.
5. **Честность.** Ограничения, стоимость и риски названы явно.
6. **Ответственность человека.** Агент готовит черновик и доказательства.

## 3. Обещание и результаты

К концу курса у слушателя есть:

- рабочая конфигурация агента и проверенная модель;
- карта проекта, реестр источников, открытые вопросы;
- `AGENTS.md` с проверенными правилами;
- два–три skills;
- описание MCP-сценария с оценкой рисков;
- требования, спецификация, ADR (если нужен);
- план проверки, доказательства и заметки ревью;
- описание командного процесса и личной среды;
- сданный capstone по рубрике.

## 4. Структура и время

| Блок | Содержание | Время | Результат |
|---|---|---:|---|
| Часть 0 | Быстрый старт, setup guide, готовность, Git-минимум | 1,5 ч | Первый артефакт и коммит |
| I. Рабочая среда | Главы 1–3 | 3 ч | Безопасная работа с файлами |
| II. Контекст и поведение | Главы 4–7 | 4 ч | Контекст, rules, skills, MCP |
| III. Артефакты | Главы 8–11 | 5 ч | Требования, спецификация, ADR |
| IV. Процесс | Главы 12–14 | 5 ч | Полный цикл, команда, безопасность |
| Сквозная практика | Пакет артефактов и ревью | 3 ч | Capstone |
| V. Ролевой трек | Один из пяти | 2–3 ч | Ролевые артефакты |
| **Итого** | **14 глав + трек** | **23,5–24,5 ч** | |

Ядро без части 0 и трека — 20 часов: части I–IV (17 ч) плюс сквозная практика (3 ч). Часть 0 добавляет 1,5 часа и не заменяет главы 1–3.

## 5. Модули

### Часть 0. Быстрый старт

| Модуль | Содержание | Проверка |
|---|---|---|
| Быстрый старт | Репозиторий → обзор проекта → `AGENTS.md` → первая задача → diff | Мини-квиз, чек-лист |
| Setup guide | Установка, модель, разрешения, диагностика | Команды проверки |
| Проверка готовности | Входной чек-лист | Шкала 0–10 |
| Git-минимум | `status`, `diff`, `restore`, коммит | Мини-практика |

### Часть I. Рабочая среда

| Глава | Содержание | Артефакт | Квиз |
|---|---|---|---|
| 1 | Модель, чат, агент; уровни действий; критерии делегирования | Черновик задачи с допущениями | Есть |
| 2 | Установка, модель, разрешения, диагностика | Конфигурация без секретов | Есть |
| 3 | Git, diff, откат, секреты | Репозиторий с историей | Есть |

### Часть II. Контекст и поведение

| Глава | Содержание | Артефакт | Квиз |
|---|---|---|---|
| 4 | Источники истины, карта проекта, противоречия | Карта проекта, реестр источников | Есть |
| 5 | Rules, `AGENTS.md`, проверка соблюдения | `AGENTS.md` | Есть |
| 6 | Skills: структура, создание, безопасность | 1–2 skills | Есть |
| 7 | MCP: привилегии, prompt injection | Описание сценария и рисков | Есть |

### Часть III. Артефакты

| Глава | Содержание | Артефакт | Квиз |
|---|---|---|---|
| 8 | Требования, допущения, критерии приёмки | Требования с ID | Есть |
| 9 | Спецификация, сценарии, трассируемость | Спецификация и ревью | Есть |
| 10 | Rules / Spec / ADR, история решений | ADR | Есть |
| 11 | Артефакты ролей, общая схема проверки | Ролевой артефакт | Есть |

### Часть IV. Процесс

| Глава | Содержание | Артефакт | Квиз |
|---|---|---|---|
| 12 | Полный цикл, change request, ошибочная спецификация | Пакет `docs/final/` | Есть |

| 14 | Данные, секреты, MCP, сборка среды | Рабочая среда и риски | Есть |
| Практика | Сквозной кейс и ревью | Capstone | Рубрика |

### Часть V. Ролевые треки

| Трек | Ключевые артефакты | Практика |
|---|---|---|
| Разработчик | План изменения, тесты, PR | 3 задания |
| QA | Тест-план, кейсы, дефект | 3 задания |
| DevOps / SRE | IaC-план, пайплайн, runbook | 3 задания |
| Аналитик | Требования, спецификация, ADR | 3 задания |
| Менеджер / продукт | Границы, риски, решения | 3 задания |

## 6. Оценивание

| Уровень | Инструмент | Вес |
|---|---|---|
| Понимание | Квиз после главы, 7 вопросов, порог 70% | Обязательно пройти |
| Умение | Практика главы и трека | Проверяется чек-листом |
| Итог | Capstone по рубрике 0–2 по семи критериям | Порог 10 из 14 |
| Сертификат | 80% квизов + зачётный capstone | Выдаётся |

Подробности: [рубрика capstone](../../content/course-unified/assessments/capstone-rubric.md), [трекер](../../content/course-unified/assessments/progress-tracker.md).

## 7. Редакционные правила

1. В ядре — «специалист», «команда», «роль»; названия ролей — в части V и таблицах адаптации.
2. Один сквозной проект — обработка заказов и уведомления о статусе.
3. Каждая глава: цели → содержание → практика → проверка → ролевые акценты → связь с базовой главой.
4. Все учебные сведения, выданные за факты, помечаются как допущения.
5. Команды и конфигурации сверяются с официальной документацией инструмента.
6. Не публиковать главу без критериев проверки.

## 9. Этапы

| Этап | Работа | Критерий готовности |
|---|---|---|
| 1 | Полный текст глав 1–14 | Глава проходит самопроверку по чек-листу |
| 2 | Эталонные артефакты и answer keys | Есть пример «плохо → хорошо» для каждой роли |
| 3 | Sandbox-репозиторий | Задания воспроизводимы с нуля |
| 4 | Диаграммы и вёрстка | PDF/EPUB без битых ссылок |
| 5 | Пилот | 15–25 участников, метрики собраны |
| 6 | Доработка по пилоту | Блокирующие замечания закрыты |

## 10. Критерии готовности главы

- [ ] Цели, содержание, практика, проверка результата.
- [ ] Ролевые акценты вынесены в таблицу адаптации.
- [ ] Ссылка на базовую главу и указание, что заменено.
- [ ] Квиз с ответами и разбором.
- [ ] Нет утверждений без источника или пометки «допущение».
- [ ] Команды проверены.
- [ ] Статус соответствует фактической готовности.

## 11. Чего не делаем

- Не создаём отдельный курс под каждую роль.
- Не обещаем трудоустройство, рост зарплаты или замену специалиста.
- Не публикуем вымышленные отзывы, метрики и кейсы.
- Не держим три копии одного текста: источник истины один.
- Не добавляем артефакт, у которого нет потребителя.
